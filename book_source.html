บทที่ 1: ภาพรวมโปรเจกต์ (Project Overview & Tech Stack)

1.1 วัตถุประสงค์ ปัญหาที่แก้ไข และใครคือผู้ใช้

ในฐานะผู้พัฒนา ผมสร้างระบบ "Planner Image Generator" (1248×1248 Canvas Engine) ขึ้นมาเพื่อแก้ปัญหาคอขวดในกระบวนการทำงานของวงไอดอล MELiMEL FRUITY♡ และทีมงานผู้ดูแลโซเชียลมีเดีย เดิมทีในทุกวันอาทิตย์หรือต้นสัปดาห์ ฝ่ายกราฟิกหรือสมาชิกในวงต้องเปิดโปรแกรมกราฟิกขนาดใหญ่อย่าง Photoshop หรือ Canva เพื่อคัดลอกตารางซ้อม นัดหมายไลฟ์สตรีม และตารางงานแสดง แล้วจัดวางข้อความทีละวัน ซึ่งกินเวลาหลายชั่วโมงและมักเกิดความผิดพลาดเรื่องการตัดบรรทัดคำภาษาไทยไม่สวยงาม หรือสัดส่วนภาพผิดเพี้ยนเมื่อนำไปทวีตบน X (Twitter) หรือโพสต์บน Instagram

ระบบนี้แก้ปัญหาโดย:

  • ระบบจัดรูปแบบภาพอัตโนมัติบนผืนผ้าใบมาตรฐาน 1248×1248 พิกเซล (1:1 HD): เป็นสเกลทองคำที่ผมคำนวณไว้แล้วว่า คมชัดเป็นพิเศษบนมือถือ ไม่ถูกโซเชียลมีเดียครอปตัดขอบหรือบีบอัดจนแตก
  • เอนจินตัดคำภาษาไทยอัจฉริยะ (Native Thai Word-Wrapping Engine): ตัดบรรทัดได้อย่างเป็นธรรมชาติ ไม่ตัดกลางสระหรือพยัญชนะ
  • One-Click Member Outline Sync: คลิกเลือกชื่อสมาชิก เช่น "น้องโมเน่ต์" ข้อมูลตารางงานซ้อม เพลงที่พร้อมขึ้นโชว์ และวันเวลาจะถูกดูดมาแมปลงในตาราง 7 วันทันทีใน 1 วินาที
  • Template Studio & Computer Vision Box Detection: ทีมงานสามารถโยนรูปตารางเปล่าลายใหม่ ๆ เข้ามา ระบบจะสแกนพิกเซลและล็อกกล่อง 7 วันให้อัตโนมัติ พร้อมใช้งานทันที

1.2 ภาษา Framework และ Library ที่ใช้ และเหตุผลที่เลือก

หลายคนอาจแปลกใจที่เห็นระบบกราฟิกที่ซับซ้อนขนาดนี้ถูกเขียนขึ้นด้วย Pure Vanilla Web Technologies (No Framework, Zero Dependencies) เหตุผลที่ผมตัดสินใจเช่นนี้คือ:

  1. Vanilla JavaScript (ES2022) + HTML5 Canvas API: ไม่ใช้ React, Vue หรือไลบรารีกราฟิกอย่าง Fabric.js / Konva.js เพราะไลบรารีเหล่านั้นมีน้ำหนักหลายร้อยกิโลไบต์ มี Virtual DOM Overhead และหน่วงเครื่องมากเมื่อต้องเรนเดอร์ภาพ 1248×1248 บนมือถือของทีมงาน การใช้ HTML5 Canvas ดิบทำให้ผมควบคุม Render Loop และ Memory ได้อย่างสมบูรณ์แบบ
  2. Intl.Segmenter API: ใช้เอนจินตัดคำระดับ Native V8 ของเบราว์เซอร์สำหรับภาษาไทย แทนการโหลดโมเดลหรือพจนานุกรมภายนอก ทำให้เว็บโหลดเร็วทันที (0 KB Dictionary Payload)
  3. Native Pointer Events API: ใช้ระบบ Pointer Events ตัวเดียวครอบคลุมทั้งเมาส์, ปากกาสไตลัส และนิ้วสัมผัสบนมือถือ/แท็บเล็ต พร้อมฟังก์ชัน setPointerCapture ป้องกันเหตุการณ์นิ้วหลุดขอบกระดาน
  4. Web Share API: แชร์รูปภาพที่สร้างเสร็จเข้าสู่แอป Twitter / Line / Facebook ได้ทันทีโดยไม่ต้องเซฟรูปลงเครื่องก่อน

1.3 โครงสร้างไฟล์และโฟลเดอร์

ผมจัดโครงสร้างโค้ดให้เรียบง่าย มีเพียง 3 ไฟล์หลักที่แยกความรับผิดชอบอย่างชัดเจน (Separation of Concerns): 

x:\TESTWEB\planner-image-tool\
├── index.html   (โครงสร้าง DOM ของหน้าจอทั้ง 3 วิว, Viewport แคนวาส, โมดอล และปุ่มควบคุม)
├── style.css    (ระบบ Design Tokens, ธีมสี Dark/Light, Responsive Layout และ Viewport Scroll/Pan)
└── app.js       (เอนจินหลักทั้งหมด: Storage, Math, Typography, Rendering, CV, Navigation & Events)

1.4 ลำดับการไหลของข้อมูลหลัก (Input → Process → Output)

  • Input: ข้อมูลข้อความ 7 วัน, ข้อมูลสมาชิกวง, สไตล์แม่แบบ, รูปภาพประกอบ และรูปพื้นหลังที่ผู้ใช้อัปโหลด
  • Process:
    1. Coordinate Matrix Projection: ปรับสเกลพิกัดนิ้ว/เมาส์จากหน้าจอจริงเข้าสู่พิกัด 1248×1248
    2. Thai Segmenter Text Wrapping: ตัดคำไทยและคำนวณความสูงของแต่ละบรรทัดให้พอดีกับความกว้างกล่อง
    3. Composite Render Pipeline: เรนเดอร์พื้นหลัง, รูปภาพพร้อมหน้ากากมุมมนและการหมุน, การ์ดตาราง 7 วัน, แบดจ์วันที่ และข้อความ
  • Output: ไฟล์ภาพ PNG ความคมชัดสูงพิเศษ (Lossless 1248×1248) หรือ JPEG 93% พร้อมดาวน์โหลดหรือส่งผ่าน Web Share

2.2 ลำดับการบูตระบบและการทำงานตอนรันจริง (Lifecycle Execution)

  1. เมื่อหน้าเว็บโหลดเสร็จ เหตุการณ์ DOMContentLoaded จะเรียก initStandalone()

  3. เรียก renderImageEditorPage():

    • เรียก pieBuildGallery() สร้างการ์ดแสดงผลบนหน้าจอ

เอนจินตัดคำภาษาไทย (Thai Word-Wrapping Engine): `pieWrap()`

นี่คือหัวใจของระบบ Typography ที่ทำให้ข้อความภาษาไทยในรูปภาพตัดบรรทัดได้ถูกต้องตามหลักไวยากรณ์: 

function pieSeg(text) {
  if (typeof Intl !== 'undefined' && Intl.Segmenter) {
    try {
      const seg = new Intl.Segmenter('th', { granularity: 'word' });
      return Array.from(seg.segment(text), s => s.segment);
    } catch(e) {}
  }
  return text.split(' '); // Fallback กรณีเบราว์เซอร์เก่า
}

function pieWrap(ctx, text, maxW) {
  if (!text) return [];
  const lines = [];
  const paragraphs = String(text).split('\n');
  for (const para of paragraphs) {
    if (!para) { lines.push(''); continue; }
    const words = pieSeg(para);
    let cur = '';
    for (const w of words) {
      const test = cur + w;
      if (ctx.measureText(test).width <= maxW) {
        cur = test;
      } else {
        if (cur) lines.push(cur);
        cur = w;
      }
    }
    if (cur) lines.push(cur);
  }
  return lines;
}

ระบบ Undo / Redo ประวัติ 50 ขั้น

ผมสร้างระบบ State Snapshot ในหน่วยความจำ โดยเก็บข้อมูลโครงสร้างฟิลด์และพื้นหลัง จำกัดความลึกไว้ที่ 50 สเต็ปเพื่อป้องกัน Memory Leak: 

const PIE_MAX_HIST = 50;
let pieHistory = [], pieHistIdx = -1;

function piePushHistory() {
  const s = pieSnapshotState(); if (!s) return;
  // ตัดกิ่งอนาคตทิ้งถ้าเคย Undo มาก่อน
  pieHistory = pieHistory.slice(0, pieHistIdx + 1);

เอนจินตรวจจับช่องตารางอัตโนมัติ (Computer Vision Algorithm): `pieAutoDetect()`

ฟังก์ชันนี้ทำหน้าที่เสมือนสายตา AI ที่ตรวจจับขอบเขตของช่องตาราง 7 วันจากภาพพื้นหลัง โดยมีขั้นตอนทางคณิตศาสตร์ 5 ขั้นตอน:

  1. Downsampling: ย่อภาพลงบน Canvas ชั่วคราวขนาด 416×416 (k = 3) เพื่อลดเวลาคำนวณลง 9 เท่า
  2. Color Thresholding: กรองพิกเซลสีขาว/สว่างจ้า (RGB >= 215 และ Delta <= 22) บันทึกลง Binary Mask
  3. 3-Pass Morphological Erosion: วนลูปกร่อนภาพ 3 รอบด้วยเคอร์เนล 3×3 เพื่อกำจัดสัญญาณรบกวนและลายเส้นแบ่ง
  4. Connected Component Labeling: ใช้ Stack-based Flood Fill ค้นหากลุ่มก้อนสี่เหลี่ยม คำนวณความหนาแน่น n / (w × h) >= 0.7
  5. Row Clustering & Field Mapping: รวมกลุ่มแถวตามแกน Y คัดกรองเหลือ 7 แถวที่มีความกว้างสูงสุด แล้วคูณสเกล k = 3 กลับสู่ขนาดจริง 1248×1248

บทที่ 4: ตัวแปรสำคัญ วงจรข้อมูล และการดักจับข้อผิดพลาด

4.1 ตัวแปรและสถานะหลัก (State Machines)

  • pieCur: เก็บสถานะของ Template ที่กำลังถูกใช้งานในหน้า Fill View (โครงสร้างธีม, รูปภาพ, รายการฟิลด์)
  • pieEd: เก็บสถานะของ Template ในห้องทดลอง Studio Editor (รวมรายการฟิลด์ที่กำลังถูกเลือก sels)
  • pieCustom: อาร์เรย์ของแม่แบบที่สร้างขึ้นเอง ซึ่งจะถูกแปลงเป็น JSON และบันทึกลง LocalStorage

4.2 การจัดการกรณีขอบ (Edge Cases) และข้อผิดพลาด (Error Handling)

สถานการณ์ / กรณีขอบ ความเสี่ยงที่อาจเกิดขึ้น วิธีที่ผมเขียนดักไว้ในโค้ด
การลากกล่องออกนอกขอบ Canvas กล่องหลุดหายออกไปนอกจอ ไม่สามารถคลิกเลือกได้อีก ใช้ Math.min(Math.max(0, x), PIE_S - w) บังคับ Clamp พิกัดให้อยู่ในกรอบ 0 ถึง 1248 เสมอ
พื้นที่ LocalStorage เต็ม เบราว์เซอร์โยน Error โค้ดพัง ข้อมูลสูญหาย ครอบด้วย try...catch ใน piePersist() ถ้าเขียนไม่ผ่านจะ Rollback ข้อมูลใน RAM และขึ้น Toast แจ้งเตือน
การเคาะปุ่มลูกศร (Nudge) รัว ๆ History Stack เต็มอย่างรวดเร็วด้วยการขยับทีละ 1px สร้างตัวหน่วงเวลา Debounce 300ms (_pieNudgeTimer) รวบการเคาะ 50 ครั้งให้บันทึกเป็น 1 สเต็ปในประวัติ
โหลดรูปภาพพื้นหลังล้มเหลว หน้าจอขาวค้าง หรือเกิด Uncaught Promise Rejection ใน pieLoadImg() ผมดัก img.onerror = () => resolve(null) เพื่อให้แอปทำงานต่อได้อย่างปลอดภัย

เนื่องจาก Canvas ถูกย่อขยายตามขนาดหน้าจอ (เช่น บนมือถืออาจกว้างเพียง 350px แต่พิกัดจริงคือ 1248px) การใช้ e.offsetX แบบปกติจะทำให้พิกัดเพี้ยนทันที ผมจึงเขียนสูตรคำนวณตัวคูณสเกล k = 1248 / offsetWidth ขึ้นมา เพื่อแปลงจุดแตะของนิ้วให้กลายเป็นพิกัดบนผืนผ้าใบจริงได้อย่างแม่นยำระดับพิกเซล
